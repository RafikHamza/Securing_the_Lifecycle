# ComMag Claim-Evidence Matrix

This matrix separates curated correctness demonstrations, runtime cryptography validation, physical Raspberry Pi measurements, diagnostic evaluation, and limited ESP32-S3 characterization.

| ID | Claim | Evidence | Status | Scope boundary |
|---|---|---|---|---|
| C1 | The industrial-safety contract declares 16 distinct protection domains and the authorized transitions between them. | `commag/contracts/industrial_safety.contract.json` | Verified | A contract specification claim, not a proof of protocol security. |
| C2 | One clean scenario and six curated misuse scenarios produce the exact expected warning-code sets. | `results/commag/security_cases.json` | Verified | Curated scenario demonstration; not a general accuracy estimate. |
| C3 | The regression suite passes 106 tests, with 5 optional native-C tests skipped in the default environment. | `results/commag/combined_test.log` | Verified | The paper evaluates the Python analyzer; native-C support is outside the present evidence scope. |
| C4 | Real TenSEAL CKKS encrypted-score evaluation and ML-KEM-1024 key encapsulation execute successfully; the cloud evaluation context has no secret key; both normal and emergency outcomes are obtained in every repetition. | `results/commag/real_crypto_validation.json` | Verified | 10 paired repetitions on Windows 11. The reported time covers two complete scenario outcomes, not an isolated primitive benchmark. |
| C5 | The Python verifier produces exact warning sets for all seven curated cases on a physical Raspberry Pi 4. | `results/rpi4/rpi4_summary.json`, `results/rpi4/rpi4_raw_runs.json`, `results/rpi4/environment_manifest.txt` | Verified | Raspberry Pi 4 Model B Rev. 1.5, aarch64, 30 repetitions per case, 210 measurements total. |
| C6 | On the Raspberry Pi 4, the clean scenario has a 19.397 ms median static-verification time and 20.271 ms P95; misuse-case medians range from 2.135 to 6.632 ms; peak recorded RSS is 24.684 MB. | `results/rpi4/rpi4_summary.json` | Verified | Static source analysis only. These values are not end-to-end sensing, cryptography, networking, or actuation latency. |
| C7 | The verifier's runtime grows approximately with program size on the supplied generated scaling fixtures. | `results/commag/scaling_benchmark.csv` | Verified for supplied fixtures | Generated programs from 48 to 2,337 actual LOC; not a real-repository benchmark. |
| C8 | The development and diagnostic corpora reveal false positives and false negatives outside the curated scenario set. | `results/commag/evaluation_results.json`, `results/commag/evaluation_summary.csv` | Verified diagnostic evidence | The diagnostic corpus was inspected during development and is not a blind benchmark. No broad accuracy claim is made. |
| C9 | The ESP32-S3 endpoint was separately identified and an initial serial capture was retained. | `commag/hardware/esp32s3/`, `commag/results/esp32s3/initial_serial_capture.txt` | Limited characterization | No aggregate ESP32-S3 timing claim is approved for the manuscript. |
| C10 | The final archives contain no configured private credentials, stale measurements, prohibited naming remnants, or pending markers. | `results/commag/release_sanitization_report.md` | Regenerated for every release | Applies only to the configured checks and files successfully extracted and inspected. |
